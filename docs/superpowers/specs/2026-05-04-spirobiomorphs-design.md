# Spirobiomorphs — Sketch Design

## Overview

A creative-coding sketch that crosses **Dawkins' biomorphs** (interactive evolution by selection, *The Blind Watchmaker*, 1986) with a **Spirograph kaleidoscope**. The user breeds rosette-like specimens by clicking children in a 3×3 grid; the clicked child becomes the new parent and 8 fresh mutants spawn around it. Specimens animate continuously — each pen traces its hypotrochoid path with a fading trail.

Working name: `spirobiomorphs`. Sketch path: `content/spirobiomorphs/`.

**Prior art / inspirations**

- Richard Dawkins' biomorphs (interactive selection-driven evolution).
- The classic Spirograph drawing toy (hypotrochoid curves via gear ratios).

## Core Interaction Loop

1. Sketch loads with a seeded **parent** specimen in the center cell of a 3×3 grid; the 8 surrounding cells are mutants of the parent.
2. User **clicks a child** → that child slides to the center, becomes the new parent, history is pushed, and 8 fresh mutants spawn.
3. **Back / Forward** buttons navigate the breeding history. Back returns to the previous parent with its original 8 children (deterministic — see *Determinism* below). Forward replays a step undone by Back.
4. **Reset** seeds a new parent, history cleared.
5. **Random** jumps to a fully random parent (full re-roll, not a mutation), pushed onto history like any other transition.
6. **Save Parent** pins the current parent to a strip below the grid for later recall.

## Genome

Each specimen carries:

### Specimen-level genes (always present)

- `palette[0..3]` — 4 HSL color slots (12 genes: H, S, L per slot)
- `k_outer` — radial-copy count for the whole composition (integer 1–12)
- `n_layers` — number of active spirograph layers (integer 1–5)

### Per-layer genes (one set per active layer, up to 5)

- `R` — fixed gear radius (integer 20–120)
- `r` — moving gear radius (integer 5–60)
- `d` — pen offset from moving gear center (integer 1–80)
- `revs` — revolutions before the pen wraps back to t=0 (integer 1–30)
- `offset` — distance from the cell origin where the layer is drawn (continuous 0–60)
- `band_count` — number of alternating draw/skip rings in the radial mask (integer 1–8)
- `band_phase` — radial offset of the band pattern (continuous 0 to band_period)
- `band_duty` — fraction of each band that draws vs skips (quantized float, 0.1–0.9 step 0.1)
- `palette_a`, `palette_b` — palette indices for the gradient endpoints (integer 0–3)
- `stroke_w` — line weight in pixels (quantized float, 0.5–4.0 step 0.5)

### Gene count

A 3-layer specimen carries 14 specimen-level + 33 layer (3 × 11) = **47 genes**. Maxes out at 69 for a 5-layer specimen (14 + 5 × 11).

### Why this shape

- `R`, `r`, `d` are kept separate so gear ratio and pen offset mutate independently of overall scale.
- Bands are encoded as `(count, phase, duty)` rather than explicit `[r_min, r_max]` pairs so a single mutation changes all bands coherently rather than scrambling them.
- A 4-slot palette with per-layer gradient indices gives specimens a recognizable identity that survives breeding (mutating a palette slot pushes every layer that references it in the same direction).

## Mutation Rules

Each of the 8 children is built from the parent by applying **N mutations**, where N is set by the **mutations-per-offspring** slider (integer 1–5, default 1).

A single mutation:

1. Pick a random gene from the parent's *active* gene list (genes belonging to layers beyond `n_layers` are inactive and ignored). Each active gene is equally weighted.
2. Apply a ±1 step change appropriate to its type:
   - **Integer genes** (`R`, `r`, `d`, `revs`, `band_count`, `palette_a/b`, `k_outer`, `n_layers`): increment or decrement by 1, clamped to range.
   - **Quantized float genes** (`stroke_w`, `band_duty`): step by their natural unit (0.5 px, 0.1).
   - **Continuous float genes** (`offset`, `band_phase`, palette H/S/L): step by ~5% of the gene's range (e.g. H steps by 18°).
3. Repeat N times, with replacement (the same gene can mutate twice).

### `n_layers` mutation special case

- **Increment:** append a new layer with median-of-range values for every layer-level gene. This keeps the new layer "neutral" so the rest of the specimen still reads.
- **Decrement:** drop the highest-indexed layer. Layer 0 is preserved as the base — `n_layers` cannot go below 1.

### Initial seed

The starting parent is generated by sampling each gene from a **curated default range** (a tighter band than the full gene range) so the user starts from a plausible spirograph rather than visual noise.

### Determinism

When breeding occurs, the RNG seed used to mutate children is stored alongside the parent in the history stack. Pressing **Back** restores the parent with its original 8 children (re-mutated from the stored seed) so navigation is reproducible — clicking the same child after going Back-Forward yields the same lineage.

## Rendering

### Per-cell buffer model

Each of the 9 grid cells owns its own `p5.Graphics` buffer (280×280 px). The main `draw()` loop:

1. For each cell, advance every active layer's pen position by `dt × pen_speed`.
2. For each layer, compute the path segments traced since the last frame and stroke them into the buffer (with the radial mask applied).
3. Composite each cell buffer onto the main canvas at its grid position.

Buffers are cleared and rebuilt only on **breed**, **back**, **forward**, **reset**, or **random**. Otherwise they accumulate continuously.

### Animated pen with fading trails

- **Pen advance.** Each layer holds a current `t`. Per frame, `t += dt × pen_speed × layer_step`. When `t > revs × 2π`, `t` wraps to 0 — the pen restarts and re-traces.
- **Fade.** Each frame, before stroking new segments, the buffer is overlaid with a low-alpha black rectangle (`fill(0, 0, 0, ~12)`). Old strokes fade gradually; high-traffic areas stay bright because new strokes overwrite the fade.
- **Background.** Each cell buffer is initialized to near-black (`#0d0d0f`) so additive blending pops. Main canvas background matches.
- **Compositing.** `blendMode(ADD)` while stroking gives additive glow. Where layers overlap, light builds.
- **Mask.** For each candidate segment, compute the midpoint distance from the layer's local origin, consult the multi-band mask, and skip the segment if it falls in a "skip" ring.
- **Symmetry stamping.** Before stroking each segment, rotate around the cell center by `(i / k_outer) × 2π` for `i ∈ 0..k_outer-1`. Each segment is stamped `k_outer` times.

### Performance budget

Worst case per frame: 9 cells × 5 layers × `k_outer = 12` × ~12 segments ≈ 6,500 stroked line segments. Comfortably 60 fps on desktop. If we hit budget pressure: reduce `pen_speed`, cap `k_outer` lower, or shrink buffer resolution.

### Grid layout

```
┌─────────┬─────────┬─────────┐
│  child  │  child  │  child  │
├─────────┼─────────┼─────────┤
│  child  │ PARENT  │  child  │
├─────────┼─────────┼─────────┤
│  child  │  child  │  child  │
└─────────┴─────────┴─────────┘
```

- Total canvas: 900×900 px (3 cells × 280 px + gutters/border).
- Parent cell visually distinguished: thicker border, slight inner glow, "Parent" label.
- Children: hover highlights border, cursor changes to pointer.
- Click animation: clicked child slides to center over ~300 ms while the old parent fades; new children mutate and fade in.

### Reuse from Nuglib

- `time/DeltaTimer` for `dt`-based pen advance.
- `color/` for HSL → RGB conversion when sampling palette gradients.
- `LayerManager` is overkill for this single-canvas pattern; skipped.
- No use of `grid/`, `fov/`, `ecs/` — this is not a roguelike sketch.

## UI

### Controls panel

A flat HTML panel directly below the canvas (matching the `schelling-segregation` pattern in this repo):

```
[◀ Back] [Forward ▶] [Reset] [Random] [💾 Save Parent]

Mutations per offspring: [───●─────] 1
Pen speed:               [─────●───] 1.0×

Generation: 12  ·  Layers: 3  ·  k=6  ·  fingerprint: a3f9
```

- **Back / Forward** — disabled at history boundaries.
- **Reset** — new seed parent, history cleared.
- **Random** — full re-roll parent, pushed onto history.
- **Save Parent** — pins to the saved-gallery strip.
- **Mutations per offspring** slider — integer 1–5, default 1.
- **Pen speed** slider — 0.25× to 4×, default 1×.
- **Status line** — current generation depth, active layer count, `k_outer`, and a 4-char hex fingerprint of the genome for visual identification.

### Saved gallery strip

Horizontally scrolling row below the controls.

- Each saved specimen rendered as a small **static** thumbnail (~120×120, frozen — no animation in the strip).
- Click a thumbnail → makes that specimen the new parent (pushed onto history; subsequent breeding diverges).
- Hover shows an **×** to remove.
- Persisted in `localStorage`, keyed by sketch name. Survives page reload; does not sync across browsers/devices.

### Keyboard shortcuts

- **1–9** (numpad layout) → pick a child. `5` is the parent, no-op.
- **Z** → Back, **X** → Forward
- **R** → Reset, **N** → Random, **S** → Save Parent
- **+ / −** → adjust mutation rate

Shortcuts are documented in a `?` tooltip in the controls panel.

## File Layout

- `content/spirobiomorphs/index.md` — Hugo frontmatter (title, description, usage, scripts, controls HTML, technical_details, citation).
- `content/spirobiomorphs/main.js` — single sketch file, target ≤ 600 lines, organized into clear sections:
  - Gene definitions (ranges, mutation step rules)
  - `mutate(parent, n)` → child genome
  - `randomGenome()` → seed; `curatedSeedGenome()` → initial parent
  - `Specimen` class — genome, `p5.Graphics` buffer, per-layer pen state; methods `step(dt)` and `render(g, x, y)`
  - History stack (parent + RNG seed per entry)
  - Saved gallery (localStorage I/O)
  - Top-level p5 sketch (`setup`, `draw`, `mousePressed`, `keyPressed`, DOM wiring)
- `content/spirobiomorphs/preview.png` — generated after the sketch is working.

If `main.js` grows past ~600 lines, split genome/mutation into a sibling file listed in the frontmatter `scripts` array.

## Out of Scope for V1

- PNG export of a specimen
- URL-encoded genome sharing
- Cross-device save sync
- Variable grid sizes (4×4, 5×5)
- Mobile touch refinements beyond p5's defaults
